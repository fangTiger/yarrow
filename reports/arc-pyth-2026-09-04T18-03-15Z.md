## 结论

- **所述“公开免鉴权 Hermes → 当前签名 → Arc 更新 → 60 秒新鲜价格”端到端路径：NO。** 最新端点实测返回 HTTP 401 `unauthorized`。
- **该 alpha 合约是否接受当前格式 Hermes 签名：NO。** 从 Base 当日 Pyth 更新交易回收的 Hermes-origin 签名 blob，在 Arc 模拟与实发均以 `InvalidWormholeVaa()` 回滚。Arc 交易哈希：`0x7fb2f44617763bc844d2b0d6252bad925fd4a55a2e2187b9fda3c47287308bcd`。
- **历史时间戳 API 能力：YES，但本部署的历史验证：NO。** 官方定义了 `/v2/updates/price/{publish_time}`；免密实取返回 HTTP 401。用同格式、发布时间为 1788544053 的签名 blob 调 `parsePriceFeedUpdates`，仍以 `InvalidWormholeVaa()` 回滚。
- **任何人无许可提交有效 Pyth 更新：YES。** `updatePriceFeeds` 是无调用者白名单的 `external payable`。是否同时触发项目结算取决于项目自己的结算入口；Pyth 不会自动调用任意业务合约。

## 设计影响

固定截止时刻结算不应依赖“先把旧价格写成当前存量值，再调用 `getPriceNoOlderThan`”。官方推荐用时间戳 API 获取历史签名，并在业务交易中调用 `parsePriceFeedUpdates(updateData, priceIds, minPublishTime, maxPublishTime)` 验证时间窗口；该函数用于固定时间价格，且不会把较旧价格强行覆盖为链上最新值。

从 2026-08-26 起，Pyth 官方文档要求 Hermes 与 Benchmarks 请求携带 `Authorization: Bearer PYTH_API_KEY`。因此当前设计还新增了一个链下可用性依赖：Pyth API 凭据及其限流/计费策略。

直接 Hermes 请求因 401 未拿到 payload。为继续验证兼容性，本次只读检索了 Base Mainnet 上同日成功的 Pyth 更新交易 `0x70d481ed8449f1b8ddbeab374f8be6ed694282caebfff43aabe0626b9455763a`，从其 `updatePriceFeedsIfNecessary` calldata 解出 1 个 2,927 字节签名 blob；该交易的 ETH/USD 事件发布时间为 1788544053，价格为 2447.37694892 USD。Arc 的 `getUpdateFee` 能解析此 blob 并返回 8 wei，但 Wormhole 验证阶段拒绝它，因此结论不是由“价格太旧”造成。

全部 ProbeVault 与 Pyth 验证结束后，测试账户 nonce 为 7，剩余原生余额 19.976883675 USDC；未耗尽资金。
