## 1. 背景与目标

现有网站是 ETHGlobal 黑客松作品「身銭を切る易者 / The Oracle Pays」：三位 AI 易者押钱预测、算错赔付、赔光封存。它的问题有三类：

1. 门槛高：每一卦都要连接钱包、签名付款，赌轨还要授权保证金。
2. 概念多：問轨/賭轨、天层/人层、Brier/BSS/Wilson、分类确认、见证结算，普通用户一个都不需要懂。
3. 文化错位：项目名、易者流派（高島易断）、视觉语言（夜の神社、麻の葉、日文字体）都是日本文化元素。

本次重构把它改造成面向中文用户、真正好用的中式命理产品「三易」。

目标：

- 一个输入框可以问任何事；第一期开放问事（六爻）、命理与运势（八字）。
- 每一术都由该术里真实存在的三个流派各自解读，形成「一问三家」。
- 凡是作为信息显示的术数元素（干支、节气、排盘、奇门、黄历）都按真实时刻推算；只作装饰的纹样使用固定经典图式。
- 视觉统一为「水墨夜」，全面去除日本文化元素。
- 继续使用 Arc 网络：收取卦金，并以区块哈希作为可复算的起卦随机源。

不做（明确移除）：

- 易者押钱、算错赔付、金库封存、Brier 计分展示。
- 可判定/不可判定双轨、到期见证结算、天层命题。
- mock/live 演示模式切换、六步进度轨、黑客松证据页（1000 回合回放、消融、墓域）。

合约、回放、消融、封存演示等脚本保留在仓库中照常可运行，但不再接入网站。

## 2. 产品定义

- 名称：三易。古称连山、归藏、周易为「三易」；本产品中又指每一术的三家解读。
- 核心体验：问一件事 → 得一张真实推算的盘 → 看三家各自怎么说、分歧在哪里。
- 三家分歧必须有典籍依据，不能硬造：

| 术 | 三家 | 依据典籍 | 判断路径 |
|---|---|---|---|
| 问事·六爻 | 程颐（义理派） | 《周易》卦爻辞、《伊川易传》的义理方法 | 卦义 → 爻义（动爻为主）→ 卦时卦德 → 处世之道 |
| | 京房（纳甲六爻） | 《京氏易传》、《增删卜易》 | 用神 → 世应 → 旺衰空破 → 动变 → 应期 |
| | 邵雍（梅花易数） | 《梅花易数》 | 体用 → 互卦 → 变卦 → 时令 → 外应（无外应信息则不用） |
| 命理与运势·八字 | 沈孝瞻（格局派） | 《子平真诠》 | 月令取格 → 成败救应 → 相神 |
| | 余春台（调候派） | 《穷通宝鉴》 | 日干配月令 → 寒暖燥湿 → 调候用神 |
| | 任铁樵（扶抑派） | 《滴天髓阐微》 | 日主强弱 → 扶抑取用 → 气势流通 |

- 三家只使用随请求提供的典籍原文作直接引文；语料库里没有的原文（例如《伊川易传》《子平真诠》全文），第一期不得直接引用，只能按该派方法论述。

## 4. 用户流程

```
首页：时空栏（此刻）＋ 一个问题框
  │ 提交
  ▼
问题分类（规则，毫秒级，不调用模型）
  ├─ 问事 ───────────────► 事项标签（决定六爻用神，可改）
  ├─ 命理 / 运势 ─► 需要生辰？─ 本机有 → 直接用
  │                        └ 没有 → 弹出生辰表单（可选择"改为起一卦问事"）
  └─ 起名/择日/星座/合婚/其它 ─► "即将开放" ＋ 改为问事的建议
  ▼
付卦金 0.05 USDC（第一期沿用现有：连接钱包，一次确认）
  ▼
问事：自动六掷（动画，约 5–8 秒）→ 排盘、奇门、黄历显示 → 三家落笔 → 白话总述
八字：命盘、大运、流年立即显示 → 三家落笔 → 白话总述
  ▼
结果页 #/r/<id>：白话总述置顶，三家依据折叠；可刷新、可分享；本机记住最近几卦
```

分类结果在提问框下以标签显示（例如「问事 · 工作／官职」「运势 · 今年」），用户可以一键改成其它类型或其它事项，改动发生在付款前，不产生费用。

## 5. 问题分类

- 位置：`src/sanyi/classify.ts`，纯函数，沿用现有 `question-classifier.ts` 的关键词规则思路与 `QUESTION_SUBJECTS` 事项表。
- 输入：原问题文本。输出：
  - `kind`：`question`（问事）｜`destiny`（命理）｜`fortune`（运势）｜`naming`｜`date-selection`｜`zodiac`｜`compatibility`｜`other`。
  - `horizon`（仅运势）：`today`｜`month`｜`year`｜`next-year`｜`year:<YYYY>`，默认 `year`。
  - `subject`（仅问事）：沿用现有七类事项及用神口径。
  - `supported`：第一期只有 `question`、`destiny`、`fortune` 为真。
  - `needsBirth`：`destiny` 与 `fortune` 为真。
- 规则示例：
  - 「我今年运势」「本月财运怎么样」→ 运势，时间范围分别为 year、month。
  - 「我适合做什么」「我的八字」「命里有没有偏财」→ 命理。
  - 「给孩子起名」→ 起名（未开放）。
  - 「下个月哪天搬家好」→ 择日（未开放）。
  - 「天蝎座」「星盘」→ 星座（未开放）。
  - 「我们合不合」「合婚」→ 合婚（未开放）。
- 无法确定时默认 `question`：问事对任何问题都能作答，且不需要生辰。
- 分类器不读取卦象或命盘，不调用模型，不下断语。
- 未开放类型给出替代建议：「起名即将开放。也可以把它当一件事来问，例如『给孩子起名叫某某好不好』」。

## 6. 生辰档案

- 表单字段：
  - 历法：公历或农历（农历需标明是否闰月）。
  - 出生日期；出生时间（精确到分钟，或选择「不知道时辰」）。
  - 性别：决定大运顺逆（阳年男、阴年女顺行，阴年男、阳年女逆行）。
  - 出生地：第 21.4 节修订后不再收集（用户反馈输入太繁琐）。
- 保存位置：浏览器 `localStorage`，只存一份「本人」档案；表单上提供「本次临时换一个生辰」。存取全部包在 try/catch 中，存储不可用时只影响「记住」，不影响排盘。
- 服务端：每次请求随附生辰，服务端只用于排盘，存档只保存排好的命盘（四柱、大运等），不保存原始生日、出生时间和出生地。
- 校正（顺序固定，每一步在命盘上标注）：
  1. 夏令时：出生时间落在 1986–1991 年中国夏令时区间内，自动减 1 小时。
  2. 真太阳时：因不收出生地，产品不做此项校正，命盘标注「未作真太阳时校正」；排盘引擎保留经度换算能力（`correctBirthTime` 的经度参数），以后需要时再开放。
  3. 换日口径：八字默认 23:00 子时换日（lunar-javascript `sect=1`），命盘上可切换为零点换日（`sect=2`），切换即重排，不重新收费。
- 不知道时辰：只排年、月、日三柱，时柱显示「缺」；三家断语必须说明缺时柱带来的限制。
- 页面告知：生辰会发送给解读模型；分享链接会显示命盘。

## 7. 六掷起卦与随机源

- 交互（第 21 节修订）：付款核验通过后，服务端自动连续完成六掷，页面自动播放铜钱落下的动画，卦从初爻向上逐爻长出；用户无需点击。原「按住摇、松开落」的亲手六掷已取消。
- 每一掷由服务端取值：
  - 第 i 掷等待并读取上一掷所用区块之后产生的第一个新 Arc 区块（第一掷取付款核验完成后的第一个新区块；Arc 单块约 0.5 秒）。
  - `h = keccak256(encodePacked("sanyi-throw-v1", 付款首笔交易哈希, 区块哈希, 规范化问题, i))`。
  - 取 `h` 最低 3 位为三枚铜钱（1 为背，0 为字），按火珠林法：一背为单（少阳 7）、二背为拆（少阴 8）、三背为重（老阳 9，动）、三字为交（老阴 6，动）。
- 约束：六掷由服务端按 1→6 顺序自动进行；每掷所用区块高度必须严格大于上一掷；已记录的掷不再重取；服务重启后从最后一次已记录的掷之后继续。
- 卦时：取第一掷所用区块的时间戳，作为日辰、月建、四柱、奇门、黄历的共同时间基准（UTC+8）。
- 可复算：付款交易哈希、六个区块哈希、规范化问题均公开存入存档，任何人可重算六爻。
- 与现有实现的关系：替代 `deriveQuestionHexagram` 的单区块一次派生；旧函数保留给旧测试与脚本。

## 8. 时空栏、黄历与奇门

### 8.1 统一时间口径

- 所有问事相关计算（六爻日辰、月建、四柱显示、奇门、黄历）使用卦时，时区 UTC+8，00:00 换日（沿用现有六爻引擎口径）；时空栏四柱对应 lunar-javascript `EightChar.setSect(2)`。
- 例外：奇门时盘按时家奇门传统以子时（23:00）换日取日柱、时柱与符头（`setSect(1)`，与参照实现 kinqimen 一致），面板标注「奇门按子时换日」。此项为编写实现计划时经实测做出的修订：kinqimen 在 2026-07-23 23:00 给出己亥日，零点换日口径会得到戊戌日并导致局数不同。
- 八字命盘另有自己的出生时刻与换日口径（见第 6 节），两套口径都在页面上标明。
- 节气月：沿用现有 `deriveSolarMonth`（太阳视黄经）；临近交节时沿用 `boundaryUncertain` 提示。

### 8.2 时空栏与黄历

- 库：`lunar-javascript`（MIT，6tail），封装在 `src/calendar/almanac.ts`。
- 时空栏字段：公历时刻；农历年月日与时辰、月相；四柱与纳音；节气、候与物候、下一节气日期；月建、日辰、旬首、旬空；建除、值神（黄道/黑道）、二十八宿、冲煞。
- 黄历面板字段：建除与值神、二十八宿、冲煞、日家九星、喜神/财神/福神方位、宜、忌（完整列表，如样例日宜 11 项、忌 7 项）、彭祖百忌。
- 一致性守卫：`almanac.ts` 输出的日干支、月建必须与 `liuyao-chart.ts` 的 `deriveSexagenaryDay`、`deriveSolarMonth` 完全一致，不一致时抛错并拒绝出结果（运行时断言＋批量测试）。
- 首页时空栏由 `GET /api/now` 按服务器当前时间计算，每分钟刷新一次；结果页时空栏按卦时显示。

### 8.3 奇门时盘

- 自研 `src/calendar/qimen.ts`：时家奇门、转盘、拆补法，与 kinqimen `Qimen.pan(1)` 同口径。
- 输出：干支、节气、阴阳遁、局数与三元、旬首与所遁六仪、值符星与所落宫、值使门与所落宫、九宫的天盘干/地盘干/九星/八门/八神、日空与时空、驿马。
- 天禽随天芮（寄坤）；中五宫只显示天盘干与地盘干。
- 八神按遁分两套：阳遁 值符、腾蛇、太阴、六合、勾陈、朱雀、九地、九天；阴遁 值符、腾蛇、太阴、六合、白虎、玄武、九地、九天。
- 值符星、值使门落中五时报告「中五」，界面显示「中五（寄坤二）」，排盘旋转按坤二计；旬首六仪在中五时值符为天禽。值符为天禽或值符落中五时中五不留天盘干，否则中五天盘干等于地盘干。
- 年柱、月柱不纳入奇门回归比较：kinqimen 在交节当日按日期切换年柱月柱（如 2026-02-04 03:01 立春前已给出丙午年庚寅月），与精确交节时刻不符；时家盘只依赖日柱、时柱与节气。
- 八门吉凶着色固定：开、休、生为吉门（石绿），伤、死、惊为凶门（朱砂），杜、景为平门（正文色）。
- 仅作显示，不输入三家断语（用户选定的「信息真算、纹样用经典图」口径）。
- 手工核验样例（2026-09-30 20:15）：丙午年丁酉月丁未日庚戌时，秋分下元阴遁四局，旬首甲辰遁壬，值符天英落坤二，值使景门落震三，死门落巽四，九天落兑七，日空、时空均为寅卯，驿马在申。
- 回归：用 kinqimen 生成至少 40 个时刻的标准答案 JSON（覆盖阴阳遁、上中下元、节气交界前后、十二时辰），存入 `tests/fixtures/qimen/`，TS 实现必须逐字段一致。

## 9. 六爻问事

### 9.1 排盘

- 沿用 `src/oracle/liuyao-chart.ts`（京房纳甲、八宫世应、六神、旬空、伏神、节气月旺衰、月破日破暗动、进退神、回头生克、六冲六合），不改算法。
- 沿用 `explicit-five-elements` 能力：五行相生环、相克星、逐爻六亲来源说明，作为排盘表下方的可展开详情。
- 沿用术语就地说明与阅读引导（`rich-liuyao-question-chart` 中「情境化术语说明与阅读引导」）。
- 事项标签决定用神；结果页修改事项时，以同一卦、同一卦时重算排盘焦点，只重跑京房一家（程颐、邵雍不依赖用神），不重新收费。

### 9.2 梅花体用（邵雍用）

- 新增 `src/calendar/meihua.ts`，由同一组六爻确定性生成：体卦、用卦、互卦（二至四爻为下、三至五爻为上）、变卦、各卦五行、体用生克关系、节气月下体卦的旺衰。
- 体用取法（铜钱卦常见多动或无动，古法梅花只有一个动爻，本站明确规定并在断语中写明「按本站取法」）：
  - 动爻全部在同一卦：该卦为用，另一卦为体。
  - 上下卦都有动爻：动爻多的一卦为用；数量相同时下卦为用。
  - 无动爻：下卦为用、上卦为体，变卦同本卦。
- 外应：本站不采集外应信息，邵雍不得虚构外应。

### 9.3 三家输入

| 家 | 输入 |
|---|---|
| 程颐 | 问题、本卦与之卦的卦辞与全部爻辞、按变占法选出的「主占之辞」、五卦名称、卦时（节气） |
| 京房 | 完整排盘事实（逐爻六神、纳甲、六亲、世应、旺衰、空破、动变、伏神）、用神/原神/忌神/仇神、月建日辰、卦辞爻辞 |
| 邵雍 | 体用互变四卦与五行、体用生克、节气月、卦辞爻辞 |

- 奇门时盘、黄历不输入任何一家。
- 主占之辞由 `src/calendar/bianzhan.ts` 按朱熹《易学启蒙》变占法确定性选出，程颐以它为主：
  - 无动爻：本卦卦辞。
  - 一爻动：本卦该动爻爻辞。
  - 二爻动：本卦两动爻爻辞，以上者为主。
  - 三爻动：本卦卦辞与之卦卦辞，以本卦为主。
  - 四爻动：之卦两不动爻爻辞，以下者为主。
  - 五爻动：之卦不动爻爻辞。
  - 六爻动：乾用「用九」、坤用「用六」，其余卦用之卦卦辞。
- 现有语料 `zhouyi-corpus.json` 只含卦辞、爻辞与用九用六，不含彖辞、象辞；第一期不补。

## 10. 八字排盘（里程碑 1B）

- 位置：`src/calendar/bazi.ts`，以 lunar-javascript `EightChar` 为底层，已核验样例（lunar-javascript 与 Python sxtwl 双源）：1990-05-15 15:30（北京时间）男命，落在 1990 年夏令时区间，按 14:30 排盘，四柱为庚午、辛巳、庚辰、癸未（未校正时时柱为甲申），起运 7 年 2 月 20 天（1997-08-04 交运），大运自壬午（8 岁）顺行。
- lunar-javascript 提供：四柱、天干十神、藏干及其十神、十二长生（地势）、纳音、胎元、命宫、身宫、起运、大运、流年、流月。
- 自研补充（`src/calendar/bazi-relations.ts`）：
  - 天干五合、天干相冲（甲庚、乙辛、丙壬、丁癸）；地支六合、三合（含有中神的半合与无中神的拱合）、三会、六冲、三刑（含自刑）、六害、破（原局之间，以及原局与当前大运、流年之间）。
  - 神煞 7 种：天乙贵人、文昌、桃花、驿马、华盖、羊刃、禄神，查表依据写入代码注释。
  - 五行分布：天干与地支本气、中气、余气分别计数，只给计数，不给「身强/身弱」结论。
  - 调候用神表：《穷通宝鉴》10 日干 × 12 月令共 120 条，只收录用神干（如「丙、癸」）与原书次序，数据文件 `src/calendar/data/qiongtong.json`。每条注明章节（如「三夏庚金」）并附逐字原文摘句；底本为维基文库全文，存于 `tools/bazi/reference/qiongtong-wikisource.txt`，测试逐条核对摘句确为底本原文、用神干都出现在摘句中。该底本没有卷次，故不标卷次。
- 运势时间范围：
  - `year`：当年流年（按立春换年）与所在大运；`next-year` 与 `year:<YYYY>` 同理。
  - `month`：当前节气月的流月。
  - `today`：当日流日干支与原局关系。
- 十年流年窗口（所有运势问题都附带）：
  - 以所问之年为锚：之前 3 年、所问之年、之后 6 年，共 10 年。`today`、`month`、`year` 的所问之年是提问时刻所在的立春年，`next-year` 为下一年，`year:<YYYY>` 即该年。
  - 为什么是「回看 3 + 展望 6」：回看的三年用户亲历过，可以拿来检验哪一家断得准，是建立信任最直接的办法；展望六年约等于大半步大运，足以看到下一次交运前后的起伏；再长则逐年短评质量下降、输出变长。
  - 每年事实：流年干支、虚岁、天干十神、地支藏干及其十神、所在大运（交运之年标交运日期），流年与原局四柱、与当年大运之间的合冲刑害（复用上面的关系计算）。
  - 边界：早于出生所在立春年的年份不列出；起运之前的年份大运记为「起运前」。
  - 样例：上面的命例在 2026-10-06 问今年运势，窗口为 2023–2032（癸卯至壬子，虚岁 34–43）；2017–2026 年为甲申运，2027-08-04 交乙酉运。
- 引擎只给客观事实；格局成败、日主旺衰、用神取舍由三家各自判断，这正是三家分歧的来源。

## 11. 命理与运势三家

| 家 | 输入 |
|---|---|
| 沈孝瞻（格局派） | 四柱、十神、藏干透出情况、月令本气与透干、合冲刑害、大运 |
| 余春台（调候派） | 日干、月令、调候表中该日干月令条目（含原文摘句）、四柱与藏干（用于判断调候用神透干或藏支）、五行分布、大运；运势另加流年与流月干支 |
| 任铁樵（扶抑派） | 四柱、十神、五行分布、通根与透干、合冲刑害、大运流年 |

- 命理（`destiny`）输出：格局或用神判断，以及性格、事业、财运、感情、健康五个分项；页面顶部有一行「三家用神对照」（例如格局派取印、调候派取丙癸、扶抑派取比劫）。命理不给吉凶等级，也没有合议线。
- 运势（`fortune`）输出：所问时间范围的吉凶等级与几成把握、分项解读、需要留意的月份或日子；有合议线。
- 运势另输出逐年列表 `years`：十年窗口每年一项 `{year, verdict, confidenceTenths, note}`，`note` ≤ 24 字（原定 16 字；短评须写出吉凶依据，真实模型实测常超 16 字而触发重写，验收前放宽）。规则：
  - 年份必须与窗口完全一致（升序、不多不少）；每项遵守 12.1 的吉凶与把握自洽约束。
  - 问整年（今年、明年、指定年份）时，所问之年那一项必须与总断的 `verdict`、`confidenceTenths` 相同。
  - `note` 中的干支、十神、关系词只能来自该年流年事实或原局事实，由 12.2 的核对器检查。
  - 结果页「流年运势」面板：十年合议走势（逐年合议 = 通过核对各家该年把握的平均）、三家最低至最高范围、五成参考线、大运交接线；下方逐年表格；点选某年显示三家该年短评。样稿见 `docs/plans/assets/2026-10-06-bazi-mockup.html`。

- **修订记录（八字样稿确认时）**：用户确认样稿，并要求增加流年运势、窗口长度由主管决定；定为回看 3 年 + 所问之年 + 展望 6 年，理由见第 10 节。同时更正命例：原文的「甲申时、起运 7 年 2 月 10 天」未做夏令时校正，校正后为癸未时、起运 7 年 2 月 20 天。

## 12. 断语输出与盘面核对（通用）

### 12.1 输出结构

每家每次一次模型调用（`StructuredOutputProvider.generateStructured`，JSON Schema 校验），三家并行。字段：

| 字段 | 问事 | 命理 | 运势 | 说明 |
|---|---|---|---|---|
| `verdict` | 必填 | 无 | 必填 | 大吉、吉、平、凶、大凶 五级 |
| `confidenceTenths` | 必填 | 无 | 必填 | 1–9，显示为「几成」 |
| `useGod` | 无 | 必填 | 必填 | 该派所取用神，一句话 |
| `headline` | 必填 | 必填 | 必填 | 一句直断，≤ 16 字 |
| `reason` | 必填 | 必填 | 必填 | 一句理由，≤ 60 字 |
| `sections` | 3–5 段 | 5 段固定分项 | 3–5 段 | `{title, text}`，按该派判断路径排序，默认折叠 |
| `timing` | 可选 | 无 | 可选 | `{window, condition}`，应期必须写明成立条件 |
| `years` | 无 | 无 | 必填 | 十年流年窗口逐年 `{year, verdict, confidenceTenths, note}`，规则见第 11 节 |
| `advice` | 1–3 条 | 1–3 条 | 1–3 条 | 可执行建议 |
| `evidence` | 必填 | 必填 | 必填 | `[{ref, claim}]`，见 12.2 |

- 自洽约束：大吉、吉 → 把握 ≥ 6 成；平 → 4–6 成；凶、大凶 → 把握 ≤ 4 成（「把握」指所问之事成、顺的把握）。不自洽视为输出无效。
- 合议线：三家把握的算术平均，标在同一条「断不成 — 断必成」轴上。

### 12.2 盘面证据核对

- `ref` 只能取服务端提供的事实编号，例如：`line:2`（六爻第二爻）、`month`、`day`、`use-god`、`body-use`、`pillar:day`、`hidden:month`、`relation:3`、`luck:current`、`tiaohou`、`year:2029`（窗口内某年的流年事实）。
- `claim` 是对该事实的陈述（如「寅木官鬼旬空」）。核对器 `src/sanyi/audit.ts` 从 claim 中抽取干支、五行、六亲、十神、旺衰字、空、破、合、冲等关键词，要求与所引事实完全一致。
- 正文 `sections` 中出现的干支与六亲/十神组合（如「寅木官鬼」「正印」）也必须能在事实表中找到。
- 不通过时带上错误说明重写一次；仍不通过，该家卡片显示「此家断语未通过盘面核对，暂不展示」，另两家照常。

### 12.3 提示词约束

- 每家系统提示词写明：所属流派、判断路径、只能引用随请求提供的原文、不得编造排盘数据、不得虚构外应、应期必须写条件、不做医疗/法律/投资结论。
- 用户可见文案不出现「押钱」「赔付」「封存」「身銭」等旧概念。
- 模型提供方：沿用现有 DeepSeek（默认）与 Anthropic provider；每卦设置 token 上限，三家并行。

## 15. 付款（第一期）

- **方式**：一笔 USDC ERC-20 `transfer`，0.050000 USDC 直接转入「三易收款地址」，钱包确认一次，不需要授权。
- **收款地址**：默认为部署记录中的 treasury `0x737301a6A40ea453A877627c409EF5756a395DB9`（项目方持有私钥），可由服务端环境变量 `SANYI_FEE_RECIPIENT` 覆盖；前端通过 `GET /api/payment` 在运行时读取收款地址与金额，不在构建产物中写死。
- **服务端核验**：读取付款交易回执，要求交易成功，且存在一条由 USDC 合约（`0x3600…0000`）发出、`from` 为付款人、`to` 为收款地址、`value` 恰为 50,000 的 `Transfer` 日志；付款凭证以交易哈希持久化防重用。
- **修订记录（1A 验收中发现）**：原方案沿用旧网站的 EIP-5792 原子批量，把卦金分三笔存入三座旧易者金库。用户实测发现 MetaMask 在 Arc Testnet 上不支持原子批量，无法付款；且旧金库合约没有提现函数，卦金会永久锁死。经用户确认改为本方案。
- **第二期**：替换为一次授权额度（收费合约，每卦自动扣款），钱包连接组件与余额检查直接复用。

## 16. 出错处理

| 情况 | 处理 |
|---|---|
| 分类无法确定 | 默认问事，标签可改 |
| 付款被拒或未上链 | 不创建 reading，按钮恢复，说明资金未变动 |
| 付款凭证已用过 | 拒绝，提示该凭证对应的已有结果链接 |
| Arc RPC 无响应（摇卦中） | 暂停摇卦，提示「未能取得天时（Arc 网络无响应），稍后可继续」；已掷的爻保留在存档，可续摇；绝不改用本地随机数 |
| 等不到新区块（>10 秒） | 同上 |
| 历法一致性断言失败 | 拒绝出结果并记录错误日志；不展示可能错误的盘 |
| 临近节气交界 | 月建旁显示「近交节」提示（沿用 `boundaryUncertain`） |
| 某一家超时、报错或输出无效 | 该卡片显示「此家暂未落笔」与重试按钮（不收费），另两家照常 |
| 免费重算次数用尽 | 每家重试 ≤ 2 次、改事项 ≤ 3 次、切换换日 ≤ 2 次；用尽后按钮置灰并说明原因，控制模型成本 |
| 某一家未通过盘面核对 | 自动重写一次；仍失败则显示「此家断语未通过盘面核对，暂不展示」 |
| 生辰不合法（如农历闰月不存在） | 表单就地提示，不提交 |
| 存储不可用（localStorage） | 只影响「记住生辰」和最近记录，不影响起卦 |

日志写入 `log/sanyi_{日期}.log`，日志内容中文，不记录原始生辰、钱包私密信息或模型密钥。

## 17. 隐私与安全

- 生辰只存本机；服务端不落原始生辰，存档只含命盘。
- 页面明示：生辰会发送给解读模型提供方；分享链接会公开显示该盘。
- 浏览器产物继续执行 `npm run frontend:secrets` 扫描：不得包含私钥、助记词、账户派生入口或任何密钥值；只注入 WalletConnect project id、Arc RPC、chain id、explorer。
- 模型密钥只从服务端 `.env` 读取。
- 三家提示词禁止医疗、法律、投资结论；涉及健康时只给传统术数意义上的提醒，并建议就医。

## 21. 验收反馈修订（2026-10-06）

用户实测后提出三点：去掉亲手摇卦；三家断语会失败（实测一卦三家全被盘面核对拦下，付了款一家都没出）；需要一个让人看得懂的整体白话解释。用户确认的取舍：自动播放六掷；三家断语内容保留现状；核对不过时删错留对；白话总述放最上面、三家折叠。

### 21.1 自动六掷

- 服务端在付款核验通过后启动后台起卦任务，逐掷调用现有的取区块与派生逻辑（第 7 节），每掷记录后立即落盘；六掷完成后排盘并启动三家。随机源与可复算口径不变。
- 前端去掉「摇」按钮。结果页轮询存档：有新掷时播放一次铜钱落下动画（约 0.8 秒）并长出对应的爻，看起来是自动连掷。
- 失败与恢复：取区块失败按退避自动重试；连续 10 分钟不可用时，页面提示「Arc 网络暂不可用，恢复后自动继续」，并给「继续起卦」按钮。服务重启时扫描未完成起卦的存档并续掷。
- 旧的单掷接口 `POST /api/readings/:id/throws` 下线（返回 404）。

### 21.2 核对修正与删错留对

- 先修 bug：问事核对器与八字核对器的问题相同，见 1B 冒烟修复（`fd99951`、`513bbff`）。做法是：卦名与爻辞原文整词处理、常用词剔除、引证改为「锚定 + 全盘存在」、事实补全神位标记、编号宽容解析。
- 重写上限：核对或 Schema 不通过时，带具体错误说明重写，最多两次（每家最多三次调用）。
- 删错留对（问事、命理、运势通用，由同一个修补函数实现）：
  1. 删去报错的证据条目；
  2. 正文（直断、理由、各段详断、建议、应期）按句号、分号、换行切句，删去含不符关键词、藏干错配、虚构组合的句子；
  3. 直断被删空时，用「{吉凶}，约{几}成」（命理用「取{用神}」）代替；某段详断被删空则整段去掉，至少保留理由；
  4. 吉凶与把握不自洽时，把把握夹到该等级允许的范围内；
  5. 运势逐年：缺漏年份记为「未给出」，多出年份删去，锚年一项对齐总断，短评不符则删去短评。
- 存档记录 `repair: { removed: N }`，不保存被删原文；卡片显示「已删去 N 处与盘面不符的内容」。
- 「此家暂未落笔」只用于模型调用失败（超时或报错）：后台自动再试一次，仍失败才显示免费重试入口。

### 21.3 白话总述

- 时机：三家都结束（落笔、修补后落笔或未落笔）后，再调用一次模型，生成总述。三家并行，总述串在其后；总述约 10–20 秒。
- 写法：中立的「三易」口吻，不借三家任何一家的身份。输出结构：
  `{ conclusion ≤40字, agreement, difference?, explanation[2–4 段], advice[2–4 条], watch?: {window, condition}, outlook?（仅运势，十年走势一句话） }`。
- 输入：问题与类型、三家输出（吉凶、几成、用神、直断、理由、详断、建议、应期；运势附逐年概要）、合议、盘面要点（卦名、本卦之卦、用神；八字四柱、大运、所问之年）。
- 约束：只依据三家与盘面，不得新增结论或盘面数据；术语首次出现须括号白话解释；吉凶倾向须与合议一致（≥ 六成偏顺，≤ 四成偏不顺，其余中性；命理不作吉凶）；医疗、法律、投资边界与文化守卫照旧。
- 核对：复用同一核对器（关键词须在本卦事实中存在，藏干与组合检查），加上倾向一致性检查；不通过时重写，最多两次，再删错留对。模型调用失败时后台自动再试一次，仍失败显示「白话总述暂未生成」与免费重试。
- 重算：改事项、换日切换、单家重试完成后重新生成总述，不收费；总述重试与三家重试分开计数，每卦各至多 2 次。
- 布局：时空栏与问题之后就是白话总述面板。面板依次是：结论（大字）、三家同异、白话解释、建议、留意时间、依据几家；三家用神对照、合议线与三张卡片折叠在「看三家依据」中，默认收起。生成期间显示进度：「起卦中」→「三家落笔中（2/3）」→「正在写白话总述」。
- 成本：每卦增加一次模型调用（DeepSeek，沿用所在服务的输出上限：问事 2048，八字 8192）；不过核对时最多再重写两次。

### 21.4 首页与生辰输入简化（用户追加）

用户反馈：问运势、命理时要填的东西太多；首页不好懂。要求生辰只收生辰八字，去掉城市与经纬度；历史收到右上角小图标；中间只留选项与输入框。

- 顶栏：左边印章与「三易」；右边依次是「卦历」小图标（时钟图形，带最近记录条数）与钱包。点「卦历」弹出浮层，列出本机最近 20 条记录（类型、问题、时间），点击打开；点浮层外或按 Esc 关闭。
- 中间单列（最大宽度约 680px，居中），自上而下依次是：
  1. 标题「想问什么？」；
  2. 三个选项：问事 / 运势 / 命理（分段按钮，默认问事）；
  3. 细项行：问事为「事项」下拉（默认自动识别），运势为「今天 / 本月 / 今年 / 明年」小标签，识别到指定年份时多出一个「某年」标签；
  4. 问题输入框，占位文字随类型变化；
  5. 运势与命理时显示内嵌生辰行；
  6. 问卦按钮与一行收费说明。
- 自动识别：输入后 400ms 防抖调用规则分类，自动切换选项与细项，并以小字提示「已自动识别为运势 · 今年」。用户手动点过类型后，不再被自动识别覆盖。识别为未开放类型（起名、星座等）时，就地提示建议，问卦按钮不可用；点「问事」即可照常问卦。
- 内嵌生辰行：
  - 公历 / 农历切换：公历用日期选择框；农历用年、月（正月至腊月）、日（初一至三十）与「闰月」勾选；
  - 时间选择框，加「不知道时辰」勾选；
  - 男 / 女切换；
  - 「记住为本人生辰（仅存本机）」勾选，默认勾上；
  - 一行告知：生辰只存本机，解读时会发送给模型，分享链接会显示命盘。
  - 无效时就地提示，问卦按钮不可用。
  - 去掉城市、经纬度、港澳台提示，以及「本次临时换一个生辰」（不勾「记住」即为临时）。
- 首页不再显示时空栏和右侧最近记录面板；时空栏只在结果页显示。
- 服务端兼容：`normalizeBirthProfile` 仍接受旧请求里的城市与经度字段（旧本机档案读出时会丢弃这两项），前端不再发送。

## 22. 第三轮反馈：解法与生辰再简化（2026-10-07）

用户反馈：这一版好多了；没看到起名；生辰填写再简化，去掉「仅存本机」之类，直接存储，去掉时辰，不填自动识别；算出后给卦象一个解法，由我们设计。

用户确认的取舍：
- 起名做成完整功能，但单独一期（另起设计，不在本节）。
- 出生时间改为选填，空着即按时辰不详排三柱。
- 解法与白话总述同一次模型调用生成。
- 不要民俗小助，即不给颜色、方位、数字、时段之类的趋避。
- 问事、运势、命理都有解法。

### 22.1 生辰再简化

- 生辰行只剩：公历 / 农历、出生日期、出生时间（选填）、男 / 女。
- 去掉「不知道时辰」勾选：出生时间留空即视为时辰不详，按年、月、日三柱排盘。日期已填而时间空着时，生辰行下方小字提示「未填时间，按年月日三柱推算」。结果页沿用现有说明：「时辰未知，缺时柱，起运按正午估算仅供参考」。
- 去掉「记住为本人生辰（仅存本机）」勾选与告知行：生辰填完整后自动存入浏览器本机存储，下次打开自动带出；存储不可用时不影响本次排盘。
- 服务端不变：仍只用随请求提交的生辰排盘，存档与日志不含原始出生日期与时间。

### 22.2 解法：位置与结构

结果页在「白话总述」之后、「看三家依据」之前，单独显示「解法」一块，问事、运势、命理都有。解法回答「那我该怎么办」，原则是有出处、能照做、不吓人、不卖东西。

| 段落 | 问事 | 运势 / 命理 |
|---|---|---|
| 心法 | 本卦《大象传》原文（如「丽泽，兑；君子以朋友讲习。」）加一句白话，说明这卦教人怎么处事 | 「三家取用」一行（沈孝瞻取某、余春台取某、任铁樵取某；调候取某某）加一句白话处事原则 |
| 怎么做（2–3 步） | 每步：做什么、依据盘面哪一点、什么时候做（结合应期，可省） | 运势：所问之年怎么过；命理：长处怎么用 |
| 别做什么（1–2 条） | 如忌神发动时先避开的人和事 | 忌神对应的事项 |

- 心法原文与「三家取用」由程序给出，不让模型编。问事取本卦的《大象传》；八字只用调候取用的天干与三家用神，不引《穷通宝鉴》原文：调候原文有的讲妻子与子女、有的带「平常人也」之类的论断口吻，还夹有维基排版符号，不适合作为处事心法。
- 模型只写心法白话、怎么做、别做什么。
- 总述原有的「建议」并入解法，不再单独输出，以免两处重复。改版前的旧存档没有解法，结果页照旧显示其「建议」。

### 22.3 解法：生成与核对

- 与白话总述同一次调用：总述 Schema 以 `remedy` 取代 `advice`：
  `remedy: { principle ≤60字, steps[2–3]: { action ≤40, basis ≤50, timing? ≤30 }, avoid[1–2] ≤40 }`。
  提示词新增「心法原文」一行（问事），八字的三家用神与调候已在输入中。
- 核对沿用总述的盘面核对：解法全部文字参与关键词核对。心法原文在核对前剔除，避免卦象用字被误判。
- 新增解法禁用词，全部总述文字都不得出现：开光、法器、符咒、符箓、护身符、转运、化煞、吉祥物、摆件、放生、捐款、供奉、烧香、幸运色、幸运数字、吉位。命中时带错误说明重写。
- 提示词明确：不给颜色、方位、数字、佩戴之类的趋避；不做医疗、法律、投资结论；不渲染恐惧，不打包票。
- 删错留对：
  - 删去不符的步骤与避忌，至少保留一步；全被删时用模板「对照下方三家依据，择其稳妥者先行」，避忌全删时用「不要据此做重大财务或医疗决定」。
  - 心法白话不符时改为「按上方原文之意，守正而行」。
- 心法原文随总述状态存档（`summary.classic: { title, text }`），分享链接可见。
- 输出长度：问事服务的模型输出上限由 2048 提到 4096，八字保持 8192。只放宽上限，不增加调用次数。
