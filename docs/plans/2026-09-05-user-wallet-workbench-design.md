# 用户钱包与单屏问卦工作台设计

本设计已由本轮产品规格直接确认，详细决策、错误处理与风险见 `openspec/changes/user-wallet-workbench/design.md`。

## 体验骨架

React SPA 顶部是不会离开视线的六步轨；中间是唯一主舞台，起初为提问与钱包状态，随后原地变为六爻仪式、可判定命题、等待倒计时和最终裁决。三张易者卡始终位于主舞台右侧，只改变内部状态。所有链上回执归入对应进度节点，不再另建重复清单。卦历通过 `#/history` 切换到独立页面。

## 钱包边界

RainbowKit `ConnectButton` 负责连接钱包，wagmi 负责切换 Arc Testnet、读取原生 18 位余额与 ERC-20 六位余额并提供用户钱包客户端。服务端仅准备 commitment 所需公开数据并核验交易；用户钱包签 `approve/commit/reveal/settle`，服务端只签三位易者预测。每次签名前都在页面交易托盘中列出卦金、保证金与预估 gas，确认后哈希立即变成 Arcscan 链接。

## 构建与安全

继续使用 esbuild，把 `web/main.tsx` 打成 ESM 与样式产物。构建入口仅允许读取并注入 `WALLETCONNECT_PROJECT_ID`、`ARC_RPC_URL`、`ARC_CHAIN_ID`、`ARC_EXPLORER` 四个公开值；浏览器代码没有环境变量入口。React 依赖可能使用 `process.env.NODE_ENV` 选择生产分支，该字面量本身不是秘密，测试会精确允许它，但继续禁止所有私钥、助记词与账户派生标识符。

## 视觉与动效

延续夜间神社终端：墨底占主导，藏青构成信息层级，朱只表达动作与最终裁决，金表达链上确认，白练用于正文。明朝体承担卦题与结果，等宽体承担地址、块高和哈希。桌面以 12 列高密度工作台呈现；移动端进度轨横向可扫、主舞台纵向紧凑，但页面根节点不横向溢出。六秒起卦仪式保留，其他动效均服务于状态变化并尊重 reduced-motion。
