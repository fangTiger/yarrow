# 三易「起名」设计（第二期）

> 日期：2026-10-09 · 状态：用户已确认方向，细节由 Claude 按用户授权代为取舍（见第 13 节）
> 关联：`docs/plans/2026-09-30-sanyi-redesign-design.md`（第一期设计，问事、命理、运势）；OpenSpec 变更 `sanyi-naming`

## 1. 目标与范围

用户在首页选「起名」，交一次卦金（0.05 USDC，与问事、命理、运势相同），得到三家各 3 个、共 9 个名字，以及一份「三家合参」，从中推荐 2–3 个并说明理由。

用户确认的取舍：
- 三家为「五行补益」「诗文出处」「音形字义」，不用五格数理：五格剖象法由日本人熊崎健翁在 1918 年前后创立，与本项目去掉日本文化元素的方向冲突。
- 还没出生的宝宝可按预产期起名，结果注明是近似。
- 每家 3 个，共 9 个。
- 既给人起名（宝宝起名、成人改名），也给公司、店铺起字号。

不做（以后再说）：五格数理；重名查询；商标与工商核名；给已有名字打分；择日、合婚。

## 2. 首页入口

- 类型选项由三项变四项：问事 / 运势 / 命理 / 起名。
- 规则分类：「起名」不再是「即将开放」。含「公司、店、品牌、商号、字号、工作室、餐厅、咖啡、茶馆、门店、企业」之一时，识别为商号，否则为人名。
- 选中「起名」后，细项行是「人名 / 商号」小标签。

### 2.1 人名

自上而下：
1. 姓氏输入框：1–2 个汉字，支持复姓，须在《通用规范汉字表》8105 字内；
2. 单名 / 双名（默认双名）；
3. 生辰行：与运势、命理相同（公历/农历、日期、时间选填、性别），另加「还没出生（按预产期）」勾选：
   - 勾选后，日期一栏改称「预产期」，时间隐藏；
   - 性别多出「不限」一项，选它就起中性名字；
4. 期望框（选填），占位文字：「对名字的期望（选填）：如温和有书卷气、第二个字用『子』字辈」；
5. 问卦按钮。

起名用的生辰单独存放，不覆盖本人生辰档案，也不自动保存。

### 2.2 商号

自上而下：
1. 「做什么生意、想要什么感觉」框，必填，至少 2 字。例：「社区咖啡馆，想要温暖安静」；
2. 字号字数：2 / 3 / 4 字（默认 2）；
3. 「加上店主生辰（选填，用于五行补益）」折叠项，展开是同样的生辰行；
4. 问卦按钮。

页面小字提示：「字号请自行查询商标与工商登记是否可用。」

## 3. 三家

| 键 | 名称 | 印 | 起法 |
|---|---|---|---|
| `wuxing` | 五行补益 | 五 | 按喜用五行选字：至少一个字属喜用五行 |
| `shiwen` | 诗文出处 | 诗 | 名字取自经典诗文中的一句，各字都出自该句 |
| `yinyi` | 音形字义 | 音 | 重读音（平仄错落、不拗口）、字形（不过繁）、字义（积极明快） |

喜用五行由程序确定，不让模型自定（第二版改为「缺的优先，调候补位」，见第 14.1 节）：
- 人名、或填了店主生辰的商号：按出生（或预产期）排四柱，用《穷通宝鉴》调候取用天干（已有 `lookupQiongtong`），换算成五行，去重后取前两个作为喜用。例：调候取丙、癸，喜用即火、水。同时列出命局五行分布供参考。
- 未填店主生辰的商号：按行业关键词查表。
  - 火：餐饮、火锅、烧烤、咖啡、烘焙、灯具、能源、传媒；
  - 水：茶、饮品、酒、水产、物流、旅游、清洁；
  - 木：教育、书店、出版、文化、花艺、园林、家具、服装、中医药；
  - 金：金融、科技、软件、汽车、五金、珠宝、机械；
  - 土：地产、建筑、农业、陶瓷、仓储、家政、物业。
  - 查不到时由五行家自选一个五行，并在 `element` 字段写明。
- 未出生按预产期排盘，时间不详，按三柱。性别为「不限」时，排盘内部按男命计算：调候与四柱跟性别无关，起名不用大运。

## 4. 字库（`src/sanyi/naming/lexicon.json`）

由 `tools/naming/build_lexicon.py` 离线构建，产物入库。原始数据下载到 `tools/naming/raw/`，不入库，来源与许可写入 `src/sanyi/naming/SOURCES.md`。

收字范围是《通用规范汉字表》（2013）全部 8105 字，按 Unihan `kTGH` 定级：1–3500 为一级，3501–6500 为二级，其余为三级。

每字字段：
- `char`：简体字。
- `pinyin`：带调拼音，取 Unihan `kMandarin` 的第一个读音。
- `tone`：1–4，轻声记 5。
- `initial`、`final`：声母、韵母。
- `trad`：繁体，取 Unihan `kTraditionalVariant`，没有则为本字。
- `kangxi`：康熙笔画 = 繁体字 `kRSUnicode` 所示康熙部首的本字笔画 + 余画。部首本字笔画取该部首字的 `kTotalStrokes`，如水 4、玉 5、艸 6、邑 7、阜 8、肉 6、辵 7、心 4、手 4、犬 4、示 5、衣 6。
  - 核对样例：泽（澤）17，瑾 16，涵 12，林 8，明 8。
- `strokes`：简体笔画（`kTotalStrokes`）。
- `level`：1、2 或 3。
- `wuxing`：五行；`wuxingBasis`：判定依据，如「部首·水」「读音·齿音」。规则如下：
  1. 按繁体的康熙部首判定：
     - 木：75 木、140 艸、118 竹、115 禾；
     - 火：86 火、72 日；
     - 土：32 土、46 山、112 石、102 田；
     - 金：167 金、96 玉；
     - 水：85 水、15 冫、173 雨。
  2. 部首不属上述时，按声母五音判定：
     - 唇音 b p m f 属水；
     - 舌音 d t n l 属火；
     - 齿音 z c s zh ch sh r 属金；
     - 牙音 j q x 属木；
     - 喉音 g k h 及零声母（含 y、w 开头）属土。
  - 页面注明：「字的五行各家说法不一，本站按字形部首优先、读音五音其次判定。」
- `meaning`：字典简短释义，不超过 24 字，只在模型未给逐字字义时兜底（名字卡的字义以模型逐字字义为主：字典首义多为古义，如「春：男女情欲」「梅：楠木」，不适合直接展示）。从新华字典数据（MIT）的 `explanation` 中取现代释义第一条（「⒈」之后到第一个「。」），去掉「～」示例；取不到为空串。
- `blocked`：不宜入名。词表维护在 `tools/naming/blocked.txt`，约 150 字，分五类：
  - 死亡疾病，如死、亡、病、疾、殁、丧；
  - 灾祸凶恶，如灾、祸、凶、恶、煞、劫；
  - 鄙俗污秽，如屎、尿、粪、脏、臭；
  - 贬损身份，如奴、婢、贱、娼、贼、盗；
  - 负面情绪，如哀、悲、愁、怨、恨、惨。

起名用字：`blocked` 为假的一、二、三级字；三级字在页面标「较生僻」。姓氏可用全部 8105 字。

## 5. 诗文语料（`src/sanyi/naming/classics.json`）

由 `tools/naming/build_classics.py` 构建，来源为 chinese-poetry（MIT）。

| 书 | 文件 | 题名写法 |
|---|---|---|
| 诗经 | `shijing.json` | `周南·关雎` |
| 楚辞 | `chuci.json` | `离骚` |
| 论语 | `lunyu.json` | `学而篇` |
| 唐诗三百首 | `唐诗三百首.json`，繁体，用 OpenCC 转简 | `作者《题》` |
| 宋词三百首 | `宋词三百首.json` | `作者《词牌》` |

- 运行时，`classics.ts` 再并入项目已有的《周易》：卦辞、爻辞来自 `zhouyi-corpus`，题名写作「乾·卦辞」「乾·初九」；《大象传》来自 `daxiang-corpus`，题名写作「乾·大象」。
- 切句：按「。！？；」切开，保留「，」，去掉引号、空白与注音括号。每句记 `{ id, book, title, text }`，`id` 为稳定编号。

候选诗句：每卦为诗文家抽 60 句。
- 条件：句中至少含名字字数个可用起名字，句长 4–24 字；
- 以解读编号为种子，确定性抽取，各书尽量均衡；
- 期望框里出现的可用字，所在诗句优先入选；
- 跳过含 `blocked` 字、以及语义明显消极的句子（含「死、亡、泣、哀、悲、愁、怨」等）。

模型只回填候选编号 `sourceId`；书名、题名、原句由程序回填，不让模型转述出处。

## 6. 模型输出与核对

### 6.1 每家输出 Schema

```
{
  note: string ≤80,                 // 本家思路：五行家写喜用与取字思路，诗文家写取材，音义家写音律思路
  element?: "木"|"火"|"土"|"金"|"水", // 仅「商号且未填店主生辰且行业查不到」时五行家必填
  names: [3 项] {
    given: string,                  // 只写名（人名不含姓；商号即字号），字数按所选
    meaning: string ≤50,            // 寓意
    why: string ≤50,                // 本家理由
    sourceId?: string,              // 诗文家必填，取自候选诗句编号
    chars: [{ char, gloss ≤12 }]    // 逐字字义：该字在这个名字里取的意思，如「泽：恩泽」
  }
}
```

### 6.2 提示词要点（三家共用的边界）

- 字须从「可用起名字」中取；五行家另给「喜用用字表」，即一级字中属喜用五行的字。
- 人名按性别取字：不限时取中性字，避免明显偏男偏女的字。
- 名字好读好写、寓意积极，避免谐音不雅（如「杜子腾」「吴理」），避免三级生僻字。
- 不用五格、三才、数理、笔画吉凶之说；不承诺改运；不出现开光、法器、符咒、转运、化煞、风水物件、放生、供奉之类。
- 商号：字号易记易读、契合行业，不用行政区划、行业词与「有限公司」之类的组织形式词。

### 6.3 程序核对（不过则带错误说明重写，最多三次调用）

通用：
- `given` 字数等于所选字数（单名 1、双名 2；商号 2–4）；
- 每个字都是可用起名字；
- 三个名字互不相同；
- `note`、`meaning`、`why` 不含禁用词：开光、法器、符咒、符箓、护身符、转运、化煞、吉祥物、摆件、放生、捐款、供奉、烧香、五格、三才、数理、天格、人格、地格、总格、外格。

分家：
- 五行家：每个名字至少一个字的 `wuxing` 属喜用。商号自选五行时，`element` 必须给出，且每个名字至少一个字属该五行。
- 诗文家：`sourceId` 必须是本卦候选编号；`given` 的每个字都出现在该句中。
- 音义家：人名的「姓 + 名」声调不得全同；名字为叠字时不受此限。

音律提示（只提示、不报错，页面显示在名字下方）：
- 姓名声调全同；
- 名字首字与姓同声母或同韵母，连读可能拗口；
- 名字含三级字（较生僻）。

### 6.4 删错留对与失败

- 三次调用后，保留通过核对的名字（至少一个），记 `removed` 处数，页面注明「已删去 N 个不合规的名字」。
- 一个合格名字都没有时，该家记为未落笔，给免费重试（每家至多 2 次）。
- 模型调用出错时后台自动再试一次（同第 21.2 节）。

## 7. 三家合参（总述）

三家结束后再调用一次模型：

```
{
  picks: 2–3 项 { given, reason ≤60 },  // 必须是本卦已通过核对的名字，互不重复
  overview: string ≤150,                 // 三家思路的异同，白话
  tips: 2–3 项 string ≤40                 // 怎么挑：念出来听、问问家人方言谐音、查重名，商号查商标
}
```

- 合参输入逐名附程序生成的音律提示；优先推荐无提示名字。若至少有两个名字没有「姓名声调全同」提示，推荐带该提示的名字须核对失败并重写。
- 人名 `tips` 不得提商标、工商；商号 `tips` 不得提重名、户口。
- 核对：`picks` 必须在合格名字里，禁用词同上。
- 修补：去掉不合格的推荐；不足两个时，取各家第一个没有「姓名声调全同」提示的合格名字，理由写「某家首选」。`tips` 不合格或与对象不符时用固定三条：
  - 「念出全名听听是否顺口」；
  - 「问问家人方言里有无不雅谐音」；
  - 人名用「上户口前查一查重名」，商号用「注册前查询商标与工商登记」。
- 调用失败：自动再试一次，仍失败给免费重试（至多 2 次）；九个名字照常可看。

## 8. 服务、存档与接口

- 新服务 `NamingReadingService`（`src/sanyi/naming/service.ts`），仿照 `BaziReadingService`：
  - 付款核验 → 排盘与喜用 → 三家并行 → 合参 → done；
  - 共用 `ReadingStore`、付款索引与日志。
- 存档 `StoredNamingReading`（`kind: "naming"`）：
  - `target`：`"person"` 或 `"business"`；
  - `question`：期望或行业说明，人名可为空串；
  - `surname`（人名）、`gender`（`male` / `female` / `any`）、`length`、`unborn`；
  - `basis`：`{ pillars, elements, tiaohou, favorable, favorableSource: "tiaohou" | "industry" | "model" }`；
  - `families`：三家状态，结构同八字三家，含 `removed`；
  - `summary`、`payment`、`createdAt`、`status`。
- 隐私：不存原始生辰（与命理相同），只存四柱与喜用。
- 公开视图：每个名字由程序附上逐字信息 `{ char, pinyin, tone, wuxing, wuxingBasis, kangxi, meaning, level }`、全名拼音、音律提示，诗文家另附 `{ book, title, text }`。
- 接口：沿用 `POST /api/readings`，请求体增加以下字段（人名须带 `birth`，商号可选）：
  - `kind: "naming"`、`target`；
  - `surname`、`gender`、`length`、`unborn`。
- 重试：`retrySchool(id, key)` 接受 `wuxing`、`shiwen`、`yinyi`；`retrySummary` 按 kind 分派。
- 首页分类接口返回 `target`。

## 9. 结果页（`web/pages/NamingReading.tsx`）

自上而下：
1. 「所问」行：「起名 · 人名（张姓 · 双名 · 女）」或「起名 · 商号（2 字）」，未出生的人名末尾增加「· 按预产期」，下面是期望原文；
2. 三家合参：推荐的 2–3 个名字（楷体大字、拼音、出自哪家、理由），再接三家异同与怎么挑；生成中显示进度；
3. 三家面板，不折叠，名字本身就是主体：
   - 每家一块：印章、家名、本家思路，再接 3 张名字卡；
   - 名字卡：全名（楷体大字）、拼音；逐字一行（字、拼音、五行及依据、康熙笔画、释义，三级字标「较生僻」）；寓意；理由；诗文家附出处（书 · 题，名字中的每个字只按出现次数依次加重原句位置）；音律提示；
4. 「起名依据」折叠：四柱（未出生注明「按预产期，时辰不详」）、五行分布、调候取用 → 喜用；商号写「按行业：咖啡 → 火」；
5. 页脚说明：五行判定规则；不用五格数理；人名上户口前查重名，商号注册前查商标与工商登记。

## 10. 出错与边界

- 姓氏不在 8105 字内：就地提示「这个姓暂不支持，请联系我们」，问卦按钮不可用。
- 期望里要求用某字，而该字不可用（不宜入名或不在字表内）：模型照常起名，合参里说明。
- 模型写了表外字或禁用字：核对不过，按上节处理。
- 文化守卫：沿用现有测试，起名页面与提示词不出现日文与五格术语。

## 11. 费用与时长

每卦 4 次模型调用（三家并行加合参），不过核对时每家另有至多两次重写。八字服务的模型配置是输出上限 8192、单次超时 90 秒。预计 30–60 秒出结果。

## 12. 测试

- 字库：
  - 8105 字齐全、等级划分正确；
  - 样例字的拼音、声调、繁体、康熙笔画、五行与依据正确（泽、瑾、涵、林、明、安、思、雨、峰、鑫）；
  - 禁用字为 `blocked`；释义非空率不低于 90%。
- 诗文：五书加《周易》都在；「关关雎鸠，在河之洲」可检索；候选抽取确定、各书均衡、不含禁用字与消极句。
- 喜用：调候换算（丙癸 → 火水）；行业表；未出生与「不限」性别可排盘。
- 核对与修补：分家的每类错误；修补保留合格名字；合参修补。
- 服务：mock 跑通人名、未出生、商号（有无店主生辰各一）；单家失败与重试；合参失败与重试；存档无原始生辰。
- 接口与分类：起名可用；人名缺姓氏或生辰时返回 400。
- 前端：首页四个选项、人名与商号表单的可用条件、起名生辰不覆盖本人档案；结果页渲染、逐字信息、出处加重、音律提示。
- 排练：`demo:rehearse` 增加人名与商号各一卦。
- 真实模型冒烟与 1320 / 390 截图走查。

## 13. 代为取舍的细节（用户睡前授权，醒来可改）

1. 未出生时性别可选「不限」，起中性名：国内不允许非医学需要的胎儿性别鉴定，多数父母事先不知道。
2. 起名用的生辰不覆盖本人生辰档案，也不自动保存。
3. 商号的店主生辰选填；不填时按行业关键词定五行，查不到由五行家自选并写明。
4. 字的五行判定按部首优先、读音五音其次，页面明示规则。

### 14.3 名字卡

每个名字（三家都有）由程序附上：

1. 字块：姓（人名）与名的每个字各一块，显示大字、康熙笔画、五行、拼音。
2. 补：名字里属补益五行的字，标「补X」，如「补金：瑶」。
3. 参考评分（0–100，程序计算）：
   - 好听（音律）：起点 96。
     - 人名姓名声调全同 −18；
     - 商号字号（2 字以上、非叠字）声调全同 −12；
     - 每条同声母或同韵母提示 −6；
     - 每个多音字 −4；
     - 每个三级字 −8。
   - 字形：起点 96。
     - 每字简体笔画 >20 画 −10，>16 画 −6；
     - 二级字每字 −2，三级字每字 −8；
     - 名字内最多与最少笔画相差 >12 −4。
   - 八字五行：
     - 按名字中属补益五行（或商号所用五行）的字的比例 r，得 70 + round(25·r)；
     - 含所缺五行再 +3，上限 98；
     - 没有补益五行时为 80。
   - 诗文意蕴：
     - 诗文家且出处已核验：96；
     - 否则语料中有一句含名字全部的字：92；
     - 否则每个字在语料中都出现不少于 5 次：84；
     - 至少一个字出现过：76；
     - 其余：70。
   - 以上四项分数下限均为 60。
   - 综合：四项平均，四舍五入。
4. 用字分析（程序生成）：每个字一句，如「「瑶」五行属金（部首·玉），补八字所缺之金；金主义，寓意果断重义、坚毅有守。」
   - 属补益五行但不属所缺的写「合所补之火」；
   - 商号写「合行业之火」；
   - 都不属的只写五行与寓意。
5. 字义分析（模型）：每个字新增 `sense` ≤30 字，写「用作名字意指……」；没有时用字典释义兜底。
6. 意蕴内涵（程序检索）：至多 3 句。
   - 先找一句含名字全部字的诗句（诗文家已作出处的那句不重复列出）；
   - 再为每个字各找一句；
   - 选句排序（审查后修订）：先取去标点后不少于 7 字的整句，再按意象分（句中宜入名字所占比例）从高到低；同分按诗经、楚辞、唐诗三百首、宋词三百首、周易、论语的书序，再按编号；
   - 过滤消极字与书名号；
   - 所用的字加重。
7. 性格标签（模型）：`tags` 3–5 个，每个 2–4 字，如「温婉」「好学」。
   - 核对禁用词与消极字；
   - 不合格时用该名字所含五行的寓意词兜底。
8. 原有的寓意、理由、出处（诗文家）、音律提示保留。

布局：
- 名字卡在桌面端每张占满一行，卡内左右两栏：
  - 左栏：字块、综合分、四项评分条；
  - 右栏：用字分析、字义分析、意蕴内涵、性格标签、寓意、理由、出处、提示。
- 宽度 ≤900px 时上下排列。
- 综合分用朱砂色小牌，评分条用主题金色单色条。
