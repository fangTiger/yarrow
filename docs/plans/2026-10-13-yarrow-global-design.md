# Yarrow（三易）面向海外：中英一键切换、八卦首页与上手引导

> 日期：2026-10-13 · 状态：定稿（主管与评审 agent 两轮讨论达成一致；用户授权主管定稿并分批交 codex 实现）

> 用户已确认：
> - 首批客户是外国人；
> - 英文品牌 Yarrow，中文名三易；
> - 轻量上手引导；
> - 英文解读采用中文生成并核对后再翻译；

## 1. 目标与成功标准

一个没接触过易经和加密钱包的英语用户，不看文档就能：
1. 理解首页；
2. 先看示例结果；
3. 装钱包、领测试币；
4. 完成问事、运势、命理、起名任一卦；
5. 用英文读懂结论与解法。

结论的正确性不能因为用户在海外而下降，所以出生时区是本期的 P0。

## 2. 出生时区（P0，G0）

问题：现有引擎把出生时间当北京时间处理，还会对 1986–1991 年套用大陆夏令时。海外用户填的是当地时间，四柱与大运会悄悄算错，运势、命理、起名都受影响。

做法：
- 生辰增加 `timeZone`（IANA 名称）：
  - 前端默认取 `Intl.DateTimeFormat().resolvedOptions().timeZone`，可修改；
  - 界面写「出生地时区 Birth time zone」，不是「当前时区」；
  - 旧存档与本机保存的旧生辰没有该字段，一律按 `Asia/Shanghai` 处理。
- 时区为 `Asia/Shanghai`（含缺省）：完全沿用现有逻辑，包括项目自带的 1986–1991 年夏令时表，不改用 tzdb。原因：
  - tzdb 还含 1940–49 年夏令时与 1901 年前的地方平时，会改动现有夹具；
  - tzdb 随 Node 内置的 ICU 版本变化，会破坏可复算。
  - 已核对：1986–1991 年这一段 tzdb 与项目表逐年一致。
- 其他时区：
  1. 当地钟面时间用 Node 自带的 `Intl.DateTimeFormat`（formatToParts 反推偏移）换算为绝对时刻 instant；迭代两次，并识别重复与跳跃时段，有歧义时取较早一个并标注。
  2. A = instant 换算成的北京钟面时间：决定年柱、月柱、胎元、大运与起运，以及出生当天是否交节。
  3. B = 当地标准时，即 instant 加上该时区的标准偏移；标准偏移取当年 1 月 1 日与 7 月 1 日两个偏移中较小者，也就是去掉夏令时。B 决定日柱、时柱。
  4. A、B 年月相同（绝大多数情况）时，直接用 B 的整组八字。
  5. 不同时（离交节约半天以内），年月取 A；十神、命宫、身宫用 LunarUtil 的表重新计算。
  6. 子时换日口径不变。
- 校正摘要写明：「按出生地时区 America/New_York，换算为当地标准时 xx:xx」。
- 不收经度、不做真太阳时，与此前一致。
- 测试：
  - 纽约、伦敦（含夏令时）、悉尼、加德满都（+5:45）的夹具，由人工换算核对；
  - 属性测试：A、B 年月相同时，拼出的八字与 lunar-javascript 直接计算的结果逐字段相等；
  - 现有中国夹具全部不变。

## 3. 英文问题的语言守卫（G0）

- 三家、总述、起名提示词写明：问题可能是英文，请仍用中文作答。
- 核对前检查汉字占比：模型输出的正文以英文为主时，判为不合格并重写。核对器是按中文关键词扫描的，英文段落会绕过核对。

## 4. 语言切换（G1 起）

- 右上角「中 / EN」一键切换整站。
- 首次访问：
  - 只在 `main.tsx` 里按 `navigator.language` 判断，`zh` 开头用中文，其余用英文；
  - 选择存 localStorage（`sanyi.lang`），读写失败时降级为浏览器语言；
  - 同步改 `<html lang>`。
- 字典：
  - `web/i18n/zh.ts` 为基准；
  - `web/i18n/en.ts` 的类型为 `Record<keyof typeof zh, string>`；
  - `useT()` 支持 `{name}` 变量；
  - 测试保证每个键的中英占位符集合一致。
- `LangProvider` 的 Context 默认值为 zh，现有中文断言基本不改；测试用 `renderIn(lang, element)` 注入语言。
- `web/lib` 下的纯函数加末位参数 `t = zhT`，不调用 hook。抛给界面的错误改为 `I18nError(key, params)`。
- 字体：在 `html:lang(en)` 下改写变量，`--brush`、`--serif` 前置 Georgia、"Times New Roman"，汉字仍回落到原字体，并收紧字距。`scripts/font-charset.ts` 的固定文案改为从 `zh.ts` 读取。
- 其他随语言切换的地方：
  - RainbowKit 的 `locale`；
  - `wagmi.ts` 的钱包名与 appName；
  - `index.html` 的 lang、title、description；
  - 服务端报错：付款、生辰、输入校验相关的报错加 `code`，前端按 code 映射；其余显示通用英文提示。
- 迁移分批：
  - G1 迁首页链路（首页、表单、生辰、付款、钱包、卦历）；
  - 结果页在 G3 接入译文时一起迁，每页只动一次。

## 5. 首页与上手引导（G1 引导部分，G4 八卦与示例）

优先级依次为：示例结果、类型卡与示例问题、随钱包状态变化的引导、八卦环。

1. 顶栏：
   - 左侧「问」印，旁边写 Yarrow，中文模式下写「三易」；
   - 右侧依次是语言按钮、卦历、钱包。
2. 八卦环：
   - 复用现有 `web/components/Luopan.tsx`（已有后天八卦，初爻朝内）；
   - 卦位固定：离上、坤右上、兑右、乾右下、坎下、艮左下、震左、巽左上；
   - 只让外圈装饰环缓慢旋转；
   - 每卦加标签，中文写「离 · 火」，英文写「Li · Fire」；
   - `prefers-reduced-motion` 时静止；
   - 手机上压低高度，保证表单留在第一屏。
3. 标题与一句话说明（中英各一）：
   - 中文：「想问什么？」／「古法起卦与八字排盘，三位古代流派各自解读，约半分钟给出白话结论。」
   - 英文：「What do you seek?」／「Ancient Chinese divination — I Ching and BaZi — read by three classical schools and explained in plain words, in about 30 seconds.」
4. 三步条：①选类型、写问题；②付 0.05 测试 USDC（Arc 测试网，不花真钱）；③得到结论、解法与三家依据。
5. 类型卡：
   - 每张卡附一句说明与 2–3 个示例问题，点一下填入；
   - 英文模式下类型必须手选，默认 Ask，不随输入自动切换；关键词只做预选提示；
   - 问事的「事项」在英文模式下必须从 7 项中选一项，关键词只做预选；感情事项写明「传统上以官鬼为用神，问妻子或女友请选 Wealth」。
6. 看看示例结果：
   - 首页入口在付款按钮之前，路由 `#/sample/<kind>`，有问事、运势、起名三卦；
   - 数据为 `web/samples/<kind>.json`，存公开视图与英文译文，由主管用真实模型生成；
   - 只读开关：隐藏重试、改事项、换日；BaziReading 传 `birth={null}`，不得读本机生辰；
   - 顶部横幅写「示例 Sample reading」。
7. 钱包与测试币引导（随状态变化）：
   - 没有钱包：桌面提示安装 MetaMask；手机提示用 MetaMask App 打开本站，给深链 `https://metamask.app.link/dapp/<host><path>`；
   - 已连接但网络不对：「一键切到 Arc 测试网（会自动添加）」；
   - 余额为 0：「复制地址」按钮，加 faucet.circle.com 链接，提示选 Arc Testnet；
   - 收款地址与 gas 估算收进「付款详情」折叠。
8. 起名（人名）对外国用户：
   - 姓氏选择器：常见 100 个姓，显示拼音、简短英文字义（如「林 Lin · forest」），可按首字母筛选；
   - 仍可直接输入汉字姓；
   - 100 个姓都必须通过 `isSurname`，英文字义人工审定。
9. 免责声明：页脚与付款区写「仅供参考与自我反思，不构成医疗、法律、投资建议」，中英各一。
10. 等待说明：
    - 问事写「六次起卦取自 Arc 区块哈希，人人可复算」；
    - 三家落笔时写「三位古代流派正在各自分析」；
    - 写总述时写「正在用白话总结」。

## 6. 英文解读：按单元翻译（G2 服务端，G3 页面）

- 生成与核对仍用中文，现有核对器不动。
- 翻译单元：

  | 类型 | 单元 | 共计 |
  |---|---|---|
  | 问事 | 总述（含解法）+ 三家各一 | 4 个 |
  | 八字 | 总述 + 三家各一；逐年短评随所在那一家 | 4 个 |
  | 起名 | 三家合参 + 三家各一 | 4 个 |

  - 每单元约 1500 字以内；
  - 总述先译，三家并发，并发上限 2–3；
  - 失败只重试该单元。
- 字段归属：

  | | 进翻译清单 | 走术语表或字典 | 不翻 / 折叠 |
  |---|---|---|---|
  | 问事 | headline、reason、sections（标题与正文）、timing、advice、总述各段、解法 | 吉凶、几成、卦名、六亲、六神、五行、事项名 | evidence 英文模式隐藏；卦辞、爻辞、大象走离线译表 |
  | 八字 | useGod、headline、reason、sections.text、advice、years.note、总述 | 命理五题标题、十神、干支（拼音）、五行 | evidence 隐藏；神煞、纳音、黄历、奇门折叠为「Traditional chart (Chinese)」 |
  | 起名 | note、meaning、why、gloss、sense、tags、合参、诗句、favorableNote | 评分标签、五德说明、提示（改为 code）、家名 | 名字保留汉字与拼音；charAnalysis 用英文模板，依据公开视图的结构化字段 |

- 输出核对：provider 是 JSON 模式，Schema 只能事后校验。另加确定性的译文核对器，检查四项：
  - 键齐全、条数一致；
  - 不含汉字，拼音术语的括注白名单除外；
  - 年份与数字保留；
  - 原文出现的术语表词，须用规定译名。
  - 不过时只把缺项与错项补译一次，仍不过则该单元记为 failed，可免费重试。
- 失效与并发：
  - `sourceHash` 按「单元原文清单 + 提示词版本 + 术语表版本」计算；
  - 只有单元已到终态（done 或 failed，且总述不在 writing）才翻译；
  - 进程内用 Map 去重；写回前再确认 hash 未变。
- 存储：旁路文件 `data/translations/<id>.en.json`，不改三种存档类型。
- 接口：
  - `POST /api/readings/:id/translate { lang: "en" }`：免费、幂等，只触发，立即返回；
  - 译文随 `GET /api/readings/:id?lang=en` 一起下发，复用现有轮询。
- 防滥用：解读 id 有 128 位随机，无法枚举。另加：
  - 全局并发信号量；
  - 同一单元失败 3 次后冷却 10 分钟；
  - 每日预算熔断（环境变量 `TRANSLATION_DAILY_UNITS`，默认 500）。
- 离线古文译表：
  - 收卦辞 64、大象传 64、爻辞 384、用九与用六 2，存 `src/agent/zhouyi-en.json`；
  - 由模型批量生成，主管抽查（含检查是否照搬 Wilhelm/Baynes 等有版权的译本），标注「Translation by Yarrow」；
  - 爻位名称用模板，如「Line 1 · Yang」「All Yin (Yong Liu)」；
  - 三家正文引用到的爻辞，把入库译文放进单元提示词，并由译文核对器保证一致。
- 术语表：`src/sanyi/i18n/glossary.ts`，纯数据，可进浏览器包，带版本号。包括：
  - 五行；
  - 八卦与 64 卦卦名（拼音加英文意译，如「Qian · The Creative」）；
  - 天干地支（拼音）；
  - 十神；
  - 六亲；
  - 吉凶；
  - 事项；
  - 起名用的五德、依据码。
- 术语写法：首次出现时写「拼音（英文释义）」，如「Yong Shen (the useful element)」，由提示词与术语表共同约束。

## 10. 主要风险

1. **生辰时区错**：结论错了，用户和我们都看不出来。由 G0 与夹具测试化解。
2. **翻译超长或条数不对**，英文页一直停在 Translating…：靠拆单元、只补译缺项、只在终态才翻译化解。
3. **外国用户付款链路断**（手机上没有钱包，或领不到测试币）：靠示例先行、状态化引导与手机深链化解。
