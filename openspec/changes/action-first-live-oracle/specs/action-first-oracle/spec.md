## ADDED Requirements

### Requirement: 动作式六段体验
系统 SHALL 以问卦为唯一首屏动作，并在提交后按成卦、三家应卦、结算、卦历、易者档案组织体验。

#### Scenario: 首次进入页面
- **WHEN** 用户尚未提交问题
- **THEN** 页面只突出问题输入、“求卦”和赔付承诺，不呈现曲线、术语或仪式动画

#### Scenario: 问题成卦
- **WHEN** 成卦完成
- **THEN** 页面自下而上展示六爻、本卦、变爻和之卦，并当场披露命题转换的解释跳跃

### Requirement: 自然语言优先与就地披露
系统 MUST 在每个专业数字之前给出自然语言解释，并把诚实性披露放在其限定元素旁边。

#### Scenario: 展示概率和评分
- **WHEN** 页面展示概率、Brier、BSS 或 Wilson 区间
- **THEN** 用户先读到“几成可能”、误差含义、相对基准表现或不确定范围，再看到小字术语与精确值

### Requirement: 可浏览且来源明确的卦历
系统 SHALL 使用同构卡片呈现 1000 回合回放和链上现场轮次，并支持结果筛选、逐批加载和点击展开。

#### Scenario: 浏览历史回放
- **WHEN** 卡片来源为回放报告
- **THEN** 卡片始终显示“历史数据回放・非现场”且不得暗示为真实用户现场占卜

#### Scenario: 浏览现场轮次
- **WHEN** 卡片来源为链上事件
- **THEN** 卡片始终显示“链上现场”以及块高、预测、结果和赔付证据

### Requirement: 易者档案
系统 SHALL 为每位易者提供资金曲线、战绩、Brier/BSS、不确定范围和永久封存墓碑状态。

#### Scenario: 打开档案
- **WHEN** 用户点击易者卡片或卦历中的易者
- **THEN** 页面展示该易者的人话表现说明、精确指标、曲线和封存状态
