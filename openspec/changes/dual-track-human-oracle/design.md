## Context

三层判定原本已经包含天、人、地，但现有产品将所有用户问题交给天层命题编译器。双轨需要先恢复问题语义，再决定是否进入责任与赔付机制。

## Goals / Non-Goals

目标：让未连接钱包的用户可直接完成問轨；让賭轨只处理有明确未来事实的问题；让用户确认并可否决分类；保持天层统计证据可见；不改变现有夜间神社终端视觉语言。

非目标：不改合约、不执行真实 DeepSeek、不跑回放或消融、不制造即时完成长周期问题的假象。

## Considered Approaches

1. 让用户勾选“可否判定”：概念负担过高，且会把产品判断推回用户，拒绝。
2. 让三位易者决定轨道：会让利益相关方控制是否进入押注，破坏命题编译器与易者分离原则，拒绝。
3. 独立分类器给出建议、用户确认并可否决：分类中立且保留用户最终决定，采用。

## Decisions

1. 分类器只接收原问题与可观察性规则；输出 `question` 或 `wager`、面向用户的理由和可复核信号。它不得导入卦象语料或三位易者模块。
2. 問轨服务只依赖只读区块源与解读 provider。种子为区块哈希和规范化问题的哈希，六爻以连续 3-bit 铜钱位派生；响应显式包含区块号、区块哈希、输入哈希、签名数 0、交易数 0、gas 0。
3. 問轨不创建 `DemoSession`，不调用钱包、`prepareRound`、合约写入或结算接口。三位易者输出是主观解读，不是可赔付概率。
4. 賭轨命题保留用户原文，`resolutionTier=human`，默认使用既有 `AttestedResolver`；需要双方声明的场景可使用 `MutualResolver`。双方冲突、缺席或提问者选择“仍无答案”均标记为未决。
5. 现场 mock 的短周期问题可即时推进到提问者见证；长周期问题停在等待态，并显示真实等待说明。
6. 卦历同时展示已结算人间事与天层 backtested 记录；数据页继续以 BSS、Wilson 与置换检验作为机制证据。

## Error Handling

- 分类器无法确定时默认建议問轨，避免未经确认触发钱包和资金路径。
- 問轨区块读取失败时返回可理解错误，不降级为伪随机或链上写入。
- 賭轨未连接钱包时只在用户确认进入该轨后提示连接，不影响返回問轨。
- 人层见证不一致、缺席或超期时进入未决，不猜测结果。

## Testing

- 表驱动测试覆盖典型规范性、心理状态、宽泛主观与明确可观察未来问题。
- 服务测试以调用计数证明問轨没有钱包、签名、交易与 gas。
- 固定区块哈希和问题重复起卦，断言六爻与输入证据完全相同。
- 賭轨测试固定一笔立誓签名、人层命题与未决语义。
- 前端内容与浏览器流程测试覆盖分类确认、否决、长周期说明、已结算人间事和天层证据位置。

## Risks / Trade-offs

- 规则分类器不可能理解所有表达；不确定时偏向免費問轨，并允许用户否决，降低误入资金路径的风险。
- `AttestedResolver` 记录标准化见证轨迹，但不让人的陈述变成 trustless 事实；UI 必须持续披露。
- 不改合约意味着实际长周期结算仍是异步流程，本轮只在 mock 中走完短周期演示，不做真实链上消费。
