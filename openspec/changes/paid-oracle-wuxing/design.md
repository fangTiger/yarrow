# 付费问卦与五行显式层设计

## Context

现有問轨绕开钱包，賭轨才支付 0.05 USDC；分类确认又增加一次必点动作。六步进度轨仍占据大块顶部空间，而五行仅以纳甲、六亲和旺衰的派生结果间接出现。既有 `DivinationRegistry` 的 treasury 为不可变地址，且本轮禁止改合约。

## Decisions

1. 标准流程改为“输入 → 求卦 → 钱包确认 → 结果”。求卦立即唤起 RainbowKit；连接后自动切 Arc、分类、检查授权并继续，不要求第二次点击。
2. 分类器建议默认生效。轨道与事项主题放入表单的可展开次级设置，用户仍可否决，但不阻塞默认路径。
3. 不可判定问题不创建押注轮次。钱包使用 EIP-5792 原子批量调用：首次批量授权三座 `DivinerVault`，随后一次批量 `deposit` 将 50,000 个 USDC 最小单位按 16,667 / 16,667 / 16,666 分账。钱包不支持原子批量时闭锁失败，不降级为三次手签或先扣一部分。
4. 可判定问题继续使用既有登记合约收取卦金和保证金。三家预测全部写入后，既有 treasury 账户预拨同额卦金，以三笔服务端转账直入三座金库；最终结算返回 treasury 的卦金用于回补。长周期或未决时由 treasury 承担垫付，不把“费用去向”推迟到事实揭晓。
5. mock 只由 `frontend:mock`、`demo:rehearse` 与测试夹具提供；主界面没有 mock/live 开关。排练中的假交易必须标为开发模拟，不能冒充免费产品路径。
6. 六步状态仍保留语义和链上凭证，但渲染为单行摘要加 `details` 展开区，主视觉高度控制在一行。
7. 五行图使用金色有向环表示相生、朱色五角星表示相克。规则层导出固定关系表和情境关系函数；UI 只消费结构化结果。
8. 本卦上下卦五行来自八经卦固定属性。逐爻说明以本卦宫五行为“我”，动态形成“生我／我生／克我／我克／同我”与六亲，并把当月旺衰和用神/原神/忌神/仇神身份接在同一处。
9. 结果态采用“答案层／解释层”两层结构：五卦、本卦卦辞、三家解读、行动、状态和一次短责任提示留在答案层；排盘、五行推导、术语、五步引导、完整披露、费用和凭证全部保留在默认关闭的原生 `details` 中。
10. 事项主题建议不再要求确认。三家解读旁显示“按事项取用神”的短行与修改下拉；改选时复用本轮付款凭证及已返回的公开区块快照重新解释，不再调用钱包，也不改变本卦。

## Error Handling

- 用户拒绝连接、切网、授权或付款时明确说明未完成步骤与未扣款状态。
- 原子批量能力不可用时停止付款，不顺序发送三笔导致部分成功。
- 付款凭证在服务端解读前核验三座金库、三笔金额与付款地址；mock verifier 仅存在于排练入口。
- 五行关系只有固定五类；任何无法归类的组合抛错，不猜测。

## Testing

- 表驱动校验五行相生、相克全表及五类六亲映射。
- 问轨服务测试证明先核验付费再调用三位解读者，并返回三库分账与一次稳态确认。
- 内容测试固定自动钱包入口、无用户可见 mock/免费文案、细状态行、五行图和逐爻情境说明。
- mock 浏览器验收桌面与移动布局，检查五卦首屏、排盘表内滚动和页面无横向溢出。
- mock 浏览器对结果态 `innerText` 去空白计数，对比精简前后默认可见字符数，并验证修改事项后区块、本卦与交易数不变。
