## Context

仓库已有六段页面骨架、统一卦历数据、三家预测和结算状态机，但视觉仍是米色纸墨风，默认模式仍是 mock，且内容层级没有充分体现“先动作，后理解”。1000 回合报告已经由只读 `/api/oracle` 规范化，演示写路径由同源 `/api/demo/*` 驱动，秘密只存在于服务端。

## Goals / Non-Goals

**Goals:**

- 在不更改接口逻辑的前提下完成动作式六段体验与高密度深色视觉。
- 把回放和现场轮次做成可筛选、逐批加载、可展开的同构卡片，同时保持来源不可混淆。
- 以自动化测试、一次 live 全链路、mock 排练和双视口浏览器验收证明交付。
- 真实调用前后记录余额差，限制模型和链上费用，不泄漏任何密钥。

**Non-Goals:**

- 不改合约、部署、`.env` 或 `/api/demo/*` 业务步骤。
- 不跑回放、消融或新增外部前端依赖。
- 不提供浅色主题、钱包连接或浏览器签名。

## Decisions

1. **沿用单页渐进状态机。** 继续复用 Web Component 与同源接口，问卦后显示 workflow；相比引入路由或框架，这能保持现有 API 与演示恢复语义不变。
2. **卡片作为唯一复用导航单元。** 应卦卡、卦历卡和档案入口共享概率、人话、链上证据字段；相比表格优先，卡片在移动端更易浏览，宽哈希仅在内部横向滚动。
3. **使用单一深色 token 系统。** 墨色渐变背景、面层、藍、朱、金、白练均由 CSS 变量提供；纵书标题和麻叶/市松底纹承担日本信号，等宽字段与辉光承担 Web3 信号。避免鸟居意象与紫色玻璃拟态。
4. **首屏静止，阶段性动效。** 首屏没有动画；六爻只在成卦阶段自下而上，朱色变爻随后出现，结算数字使用平滑缓动；降低动态偏好时全部即时完成。
5. **LIVE 默认受验证门禁约束。** 先将费用安全阈值收紧到 1.5 USDC，再只跑一轮 live。仅在命题编译、三家 reasoning、三笔预测和三笔结算全部通过后更新默认；失败则保留 mock。

## Risks / Trade-offs

- [live 调用缺字段或超时] → 不重试、保存脱敏审计、保持 MOCK 默认并报告失败。
- [链上窗口在顺序推理时过期] → 沿用截止块余量检查和自动守候结算。
- [1000 张卡造成 DOM 压力] → 初始 12 张、逐批加载，筛选后重置批次。
- [深色密集布局移动端溢出] → 根页面禁止横向滚动，哈希/交易带使用局部滚动并做 390px 验收。
- [在线字体不可达] → 使用本机日文明朝与中文宋体回退栈，不依赖 CDN。

## Migration Plan

1. 先以测试固定预算、信息架构、来源标签、默认模式与视觉 token。
2. 在保持 mock 默认时执行唯一 live 验证；通过后再切默认 LIVE。
3. 构建静态产物，完成 mock、密钥和浏览器验收。
4. 若 live 失败，只回退默认模式相关变更，其他前端重构仍可独立交付。
